# KwargsBuilder Derive Macro

A procedural macro for generating builder patterns for Python keyword arguments (kwargs) when using PyO3.

## Purpose

When wrapping Python libraries with PyO3, Python functions often have many optional parameters. This macro automates the builder pattern for such parameters, making your Rust API clean and ergonomic while seamlessly integrating with PyO3's Python interop.

## Features

- ✅ **Automatic builder methods** - Generates setters for all `Option<T>` fields
- ✅ **Clean API** - Setters take `T` instead of `Option<T>`, wrapping values automatically
- ✅ **PyO3 integration** - Generates `get_kwargs()` that creates a PyDict with only set values
- ✅ **Selective skipping** - Use `#[kwargs_builder(skip)]` for custom handling of complex types
- ✅ **Zero boilerplate** - Focus on your API, not repetitive setter code

## Installation

Add to your `Cargo.toml`:

```toml
[dependencies]
kwargs_builder_derive = { path = "../kwargs_builder_derive" }
pyo3 = "0.27"
```

## Basic Usage

```rust
use kwargs_builder_derive::KwargsBuilder;
use pyo3::{Python, PyResult};

#[derive(KwargsBuilder)]
struct PlotBuilder {
    x: Vec<f64>,              // Required field (not Option)
    y: Vec<f64>,              // Required field (not Option)
    color: Option<String>,    // Optional - builder method generated
    linewidth: Option<f64>,   // Optional - builder method generated
    alpha: Option<f64>,       // Optional - builder method generated
}

impl PlotBuilder {
    pub fn set(self) -> PyResult<()> {
        Python::with_gil(|py| {
            let plt = py.import("matplotlib.pyplot")?;
            let kwargs = self.get_kwargs(py)?;  // Generated by macro

            plt.call_method("plot", (self.x, self.y), Some(&kwargs))?;
            Ok(())
        })
    }
}

// Usage - clean and ergonomic!
fn plot(x: Vec<f64>, y: Vec<f64>) -> PlotBuilder {
    PlotBuilder {
        x, y,
        color: None,
        linewidth: None,
        alpha: None,
    }
}

plot(vec![1.0, 2.0, 3.0], vec![1.0, 4.0, 9.0])
    .color("blue".to_string())  // No Some(...) needed!
    .linewidth(2.0)
    .alpha(0.7)
    .set()
    .unwrap();
```

## What Gets Generated

For the example above, the macro generates:

```rust
impl PlotBuilder {
    pub fn color(mut self, value: String) -> Self {
        self.color = Some(value);
        self
    }

    pub fn linewidth(mut self, value: f64) -> Self {
        self.linewidth = Some(value);
        self
    }

    pub fn alpha(mut self, value: f64) -> Self {
        self.alpha = Some(value);
        self
    }

    pub fn get_kwargs<'py>(&self, py: Python<'py>) -> PyResult<Bound<'py, PyDict>> {
        let kwargs = PyDict::new(py);
        if let Some(ref value) = self.color {
            kwargs.set_item("color", value)?;
        }
        if let Some(ref value) = self.linewidth {
            kwargs.set_item("linewidth", value)?;
        }
        if let Some(ref value) = self.alpha {
            kwargs.set_item("alpha", value)?;
        }
        Ok(kwargs)
    }
}
```

## Advanced Usage: `#[kwargs_builder(skip)]`

Use the `skip` attribute when you need custom type conversion logic or want to handle a field manually:

```rust
use kwargs_builder_derive::KwargsBuilder;
use ndarray::Array1;

// Custom enum for parameters that accept multiple types
pub enum ScatterSize {
    Scalar(f64),
    Array(Array1<f64>),
}

// Implement From traits for automatic conversion
impl From<f64> for ScatterSize {
    fn from(value: f64) -> Self {
        ScatterSize::Scalar(value)
    }
}

impl From<Array1<f64>> for ScatterSize {
    fn from(value: Array1<f64>) -> Self {
        ScatterSize::Array(value)
    }
}

#[derive(KwargsBuilder)]
struct ScatterBuilder {
    x: Array1<f64>,           // Required
    y: Array1<f64>,           // Required

    // Skip auto-generation for custom handling
    #[kwargs_builder(skip)]
    s: Option<ScatterSize>,

    // Regular optional parameters still get auto-generated
    marker: Option<String>,
    alpha: Option<f64>,
}

impl ScatterBuilder {
    // Manually implement generic setter for skipped field
    pub fn s<T: Into<ScatterSize>>(mut self, value: T) -> Self {
        self.s = Some(value.into());
        self
    }

    pub fn set(self) -> PyResult<()> {
        Python::with_gil(|py| {
            let kwargs = self.get_kwargs(py)?;  // Only includes marker, alpha

            // Manually handle the skipped field with custom conversion
            if let Some(size) = self.s {
                match size {
                    ScatterSize::Scalar(val) => kwargs.set_item("s", val)?,
                    ScatterSize::Array(arr) => kwargs.set_item("s", arr.into_pyarray(py))?,
                }
            }

            // ... call Python method
            Ok(())
        })
    }
}

// Usage with automatic type conversion!
scatter(x, y)
    .s(100.0)                    // f64 -> ScatterSize::Scalar
    .s(arr1(&[50.0, 100.0]))     // Array1 -> ScatterSize::Array
    .marker("o".to_string())
    .alpha(0.7)
    .set()
    .unwrap();
```

## How It Works

1. **Identifies Optional Fields**: Scans your struct for `Option<T>` fields
2. **Generates Setters**: Creates builder methods that take `T` and wrap it in `Some(T)`
3. **Respects Skip Attribute**: Ignores fields marked with `#[kwargs_builder(skip)]`
4. **Creates PyDict Helper**: Generates `get_kwargs()` that only includes `Some` values

## Requirements

- Struct must have named fields
- Only `Option<T>` fields get builder methods
- PyO3 must be available for `get_kwargs()` method
- Field types must implement `IntoPyObject<'py>` for PyO3 conversion (or be manually handled with `skip`)

## Benefits Over Manual Implementation

**Without KwargsBuilder:**
```rust
impl PlotBuilder {
    pub fn color(mut self, value: Option<String>) -> Self {  // Verbose!
        self.color = value;
        self
    }
    // ... repeat for every optional field
}

// Usage requires Some(...)
builder.color(Some("red".to_string()));  // Annoying!
```

**With KwargsBuilder:**
```rust
#[derive(KwargsBuilder)]  // That's it!
struct PlotBuilder { /* ... */ }

// Usage is clean
builder.color("red".to_string());  // Beautiful!
```
