## Project Overview

matplotlib-rs is a Rust wrapper for Python's matplotlib library using PyO3. It provides a Rust-native API that mirrors matplotlib's plotting interfaces, currently supporting two main patterns:
- Direct plotting via `plt.plot` (planned)
- Subplots-based plotting via `plt.subplots` (implemented)

## Build Commands

```bash
# Build the project (workspace with two crates)
cargo build

# Run the example binary
cargo run --bin matplotlib

# Build just the library
cargo build -p matplotlib

# Build the proc-macro crate
cargo build -p kwargs_builder_derive

# Check for compilation errors
cargo check
```

## Architecture

### Workspace Structure

This is a Cargo workspace with two crates:
- `matplotlib/` - Main library that wraps matplotlib via PyO3
- `kwargs_builder_derive/` - Procedural macro crate for builder pattern generation

### Core Design Pattern: Builder Pattern with Deferred Execution

**CRITICAL ARCHITECTURAL RULE**: For any Python function with optional parameters, you MUST use the builder pattern with `#[derive(KwargsBuilder)]`. The function returns a builder struct, and Python code execution is deferred until `.set()` is called.

Example from `subplots.rs`:
```rust
// 1. Define builder struct with KwargsBuilder derive
#[derive(KwargsBuilder)]
pub struct SubPlotsBuilder {
    nrows: usize,              // Required parameters
    ncols: usize,
    sharex: Option<bool>,      // Optional parameters as Option<T>
    sharey: Option<bool>,
    // ...
}

// 2. Implement .set() method that executes Python code
impl SubPlotsBuilder {
    pub fn set(self) -> PyResult<(Figure, Array2<Axes>)> {
        Python::attach(|py| {
            let plt = py.import("matplotlib.pyplot")?;
            let kwargs = self.get_kwargs(py)?;  // Generated by KwargsBuilder
            let result = plt.call_method("subplots", (self.nrows, self.ncols), Some(&kwargs))?;
            // ... process result
        })
    }
}

// 3. Public function returns the builder
pub fn subplots(nrows: usize, ncols: usize) -> SubPlotsBuilder {
    SubPlotsBuilder {
        nrows,
        ncols,
        sharex: None,
        sharey: None,
        // ...
    }
}
```

**Usage pattern**:
```rust
let (fig, axes) = plt::subplots(2, 2)  // Returns builder
    .sharex(Some(true))                // Optional parameter
    .sharey(Some(false))               // Optional parameter
    .set()                             // Executes Python code
    .unwrap();
```

### How KwargsBuilder Works

The `#[derive(KwargsBuilder)]` proc macro automatically generates:
1. **Builder methods** for all `Option<T>` fields (e.g., `.sharex(value)`, `.sharey(value)`)
2. **`get_kwargs(py)` method** that creates a PyO3 `PyDict` containing only the `Some()` values

This allows Rust code to ergonomically mirror Python's `func(required, optional=value)` pattern.

### PyO3 Integration Architecture

The library uses PyO3's `auto-initialize` feature to manage the Python interpreter. Key patterns:

1. **Python Attachment Pattern**: All Python calls use `Python::attach(|py| { ... })` to ensure thread-safe access
2. **Wrapper Structs**: Rust structs (`Figure`, `Axes`) hold `Py<PyAny>` to store Python objects across the FFI boundary
3. **Result Propagation**: All Python interactions return `PyResult<T>` for error handling

### Module Organization

```
matplotlib/src/
├── lib.rs                    # Root module, exports show() function
└── pyplot/
    ├── mod.rs                # Module declarations and re-exports
```

The `pyplot` module is organized to mirror matplotlib's API structure. New plotting methods should be added as `impl` blocks in separate files under `pyplot/axes/`.

## Adding New Matplotlib Functions

### For Functions WITH Optional Parameters (MOST CASES)

Follow the builder pattern with deferred execution:

1. **Create a builder struct** in the appropriate module file
2. **Derive KwargsBuilder** and add required params as regular fields, optional as `Option<T>`
3. **Implement `.set()` method** that executes the Python code
4. **Create public function** that returns the builder

Example for `axes.scatter()`:
```rust
#[derive(KwargsBuilder)]
pub struct ScatterBuilder {
    x: Array1<f64>,           // Required: 1D array
    y: Array1<f64>,           // Required: 1D array
    s: Option<f64>,           // Optional: marker size
    c: Option<String>,        // Optional: color
    marker: Option<String>,   // Optional: marker style
}

impl ScatterBuilder {
    pub fn set(&self, axes: &Axes) -> PyResult<()> {
        Python::attach(|py| {
            let axes_obj = axes.inner.bind(py);
            let kwargs = self.get_kwargs(py)?;
            axes_obj.call_method("scatter", (self.x.clone(), self.y.clone()), Some(&kwargs))?;
            Ok(())
        })
    }
}

impl Axes {
    pub fn scatter(&self, x: Array1<f64>, y: Array1<f64>) -> ScatterBuilder {
        ScatterBuilder {
            x, y,
            s: None,
            c: None,
            marker: None,
        }
    }
}
```

### For Simple Methods WITHOUT Optional Parameters (RARE)

Only use direct implementation if the method has zero optional parameters:

```rust
impl Axes {
    pub fn method_name(&self, required_params) -> PyResult<()> {
        Python::attach(|py| {
            let axes = self.inner.bind(py);
            axes.call_method("method_name", (params,), None)?;
            Ok(())
        })
    }
}
```

## Type Conversions and Data Handling

### Input Data Types

**IMPORTANT**: Plot methods must accept `ndarray` types as inputs, not `Vec`:
- **1D data**: Use `ndarray::Array1<f64>` for single arrays (e.g., `plot(x, y)`, `hist(data)`)
- **2D data**: Use `ndarray::Array2<f64>` for 2D arrays (e.g., `contour(Z)`, `pcolormesh(C)`)
- **2D or 3D data**: Use `ndarray::ArrayD<f64>` for flexible dimensions
  - `imshow` accepts both 2D (grayscale) and 3D (RGB/RGBA) arrays

The choice between 1D, 2D, and dynamic dimensions depends on the matplotlib function being wrapped:
- `plot`, `scatter`, `bar`, `hist`: Accept `Array1<f64>`
- `contour`, `contourf`, `pcolormesh`: Accept `Array2<f64>`
- `imshow`: Accept `ArrayD<f64>` (2D for grayscale, 3D for RGB/RGBA images)

### PyO3 Conversions

- `ndarray::Array1<f64>`, `ndarray::Array2<f64>`, and `ndarray::ArrayD<f64>` → Python arrays (automatic via PyO3)
- `ndarray::Array2<Axes>` is used for 2D subplot arrays (see `subplots.rs:49`)
- Always use `squeeze=false` for subplots to ensure consistent 2D array output

## Important Notes

- The `edition = "2024"` in Cargo.toml requires Rust 1.85.0+ (nightly as of project creation)
- Python matplotlib must be installed in the environment where this runs
- The proc macro only generates code for `Option<T>` fields - required fields must be constructor parameters
- **Always use the builder pattern for functions with optional parameters** - this is not optional, it's the architectural standard
- **Always use ndarray types for data inputs** - use `Array1<f64>` for 1D data, `Array2<f64>` for 2D data, and `ArrayD<f64>` when multiple dimensions are possible
